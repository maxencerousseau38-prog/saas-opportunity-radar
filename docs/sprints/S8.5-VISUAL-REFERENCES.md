# S8.5 — Visual references (PD-38)

**Date:** 12 November 2026 · **Decision:** PD-38 (amendment of ADR-016),
approved by the product owner in session ("les deux, lance").

## Why

Every Discover card showed "Aperçu authentique non disponible": PD-36 only
allowed operator-admitted private copies with documented rights, one by one,
and none were documented. The product owner asked for visuals on the whole
catalog, automatically.

## What

| Kind | Source | Rights shown | Stored |
|---|---|---|---|
| `licensed_image` | Wikidata image (P18) on Wikimedia Commons | Licence (CC0, PD, CC BY, CC BY-SA), author, file page | Reference only |
| `publisher_share_image` | `og:image` / `twitter:image` of the official site | "Image de partage publiée par l'éditeur", no licence implied | Reference only |
| existing private copy | Operator manifest (PD-36) | Documented rights | Private copy |

Precedence on a card: approved copy > free licence > share image. A
reference whose origin is gone falls back to the honest state.

## Why by reference

The Supabase organisation is on the free plan (500 MB database): thousands
of image copies would not fit, and storing them would reproduce the images.
The CSP already allows `img-src https:`; images load without referrer.

## Pipeline

1. *Catalog visuals* workflow (GitHub runners; this cloud session cannot open
   direct connections): `visuals.js collect licensed|publisher` from the
   committed catalog snapshots → `data/visuals/*.json`, validated.
2. Loading (manual, per environment): `visuals.js ingest` →
   `sor_record_visual_reference` (service role; evidence-linked, audited,
   idempotent; refuses non-free licences, http, off-domain share images and
   products that are not visible).

## Order for production

1. Merge (the web contract accepts the old DTO, so deploying first is safe).
2. Apply `20261125090001_visual_references.sql` to the hosted project.
3. Load `data/visuals/*.json` once the catalog import is complete.

## Not done

- No automatic screenshots, no generated images, no logo APIs.
- No periodic revalidation of references yet (a broken image already falls
  back on the card); the operator can remove any reference at once.
